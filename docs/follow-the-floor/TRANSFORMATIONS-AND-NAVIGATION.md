## Stair quality gate

The existing media do not contain a genuine walk up the approved pearl stairs. A local Blender prototype was authored and reviewed, but its architecture/materials did not match the visual quality of the current image. It was rejected before full animation rendering. The public route continues to use the approved pearl still and detail lens, with longer entrance/departure transitions. It is **not a new stair video**.

A tested future-film timing helper holds the first frame for 0–14% of chapter travel, traverses during 14–84%, and holds the landing afterward. It is inert while the foundation chapter is still-only. The reproducible builder remains marked `study-unready`; variant staging and failed-recovery handling have regression coverage.

## Bugs caught during this iteration

1. Native browser image dragging cancelled comparison drags. Project images now disable native dragging while preserving accessible descriptions.
2. Shared navigation forgot the saved pause preference on direct non-home visits. The header hydrates the preference and maintains its own still-state hook.
3. Mobile section padding narrowed the gallery viewport, clipping the last card. The white gallery stage is full-width with its own content gutters.
4. Mobile captions trapped vertical touch scrolling. They now allow both axes; only the image comparison owns horizontal editing.
5. Two generic WebKit `load` waits timed out during the first combined run. Tests now wait for HTML readiness and then assert the specific hydrated controls/decoded media under test; media-readiness checks were not removed.

No physical-device certification, live quote delivery, provider processing, repository push, Hostinger deployment or live-domain cutover occurred in this refinement.
